SIEM_PROJECT · Wazuh 4.14.9 · scénario joué le 2026-10-22

Détection d'un brute force SMB sur Windows 11

Kali devine le mot de passe du compte analyste en SMB. Chaque essai raté laisse un événement 4625 dans le journal Security de Windows. L'agent l'envoie à Wazuh, qui lève une alerte par échec, puis une alerte de corrélation, puis l'alerte du succès. Les règles et les niveaux ci-dessous sont ceux observés dans le dashboard.

① Sans accès réseau, rien à détecter

Le pare-feu Windows limite par défaut le partage de fichiers (SMB 445) au sous-réseau local. Kali étant sur 10.10.20.0/24, ses paquets étaient jetés sans bruit : pas d'authentification, donc pas de 4625. Il a fallu une règle entrante autorisant 10.10.20.0/24. Un silence dans le SIEM peut vouloir dire « rien n'est arrivé jusqu'à la cible ».

② La console de l'attaquant ment

nxc n'a affiché que le succès et des « Connection Error / NETBIOS timed out » pour les échecs. Pourtant Wazuh a reçu 10 événements 4625 : chaque tentative a bien été authentifiée par Windows. Un timeout côté outil ne veut pas dire « pas de tentative ». La source de vérité, ce sont les journaux défensifs.

Lire un 4625

subStatus 0xC000006A : le compte existe, le mot de passe est faux. 0xC0000064 voudrait dire « utilisateur inconnu ». Ici l'analyste apprend que l'attaquant visait un compte réel. logonType 3 = ouverture réseau (SMB), pas une session au clavier.

Le signal qui compte : le succès après la rafale

60204 dit « quelqu'un essaie ». 92652 juste après, pour le même compte, dit « il a réussi ». C'est cette suite qui fait passer d'une tentative à une compromission. Wazuh ne relie pas les deux d'office : une règle locale peut le faire (proposition dans la fiche, à valider).

MITRE : une étiquette à corriger

L'attaque est un T1110 Brute Force (Credential Access). La règle 60204 le dit. La règle 60122, elle, porte nativement T1531 (Account Access Removal, tactique Impact) : l'étiquette ne décrit pas ce qui se passe. À ne pas recopier telle quelle dans un rapport.

Règles 60122 et 60204 : ruleset Wazuh v4.14.0, 0580-win-security_rules.xml ($MS_FREQ = 8, timeframe 240 s, même win.eventdata.ipAddress). Règle 92652 : description relevée dans le dashboard, fichier du ruleset à identifier. Comptes et niveaux observés dans le lab ; seule l'heure du succès (02:15:46) est reportée.
